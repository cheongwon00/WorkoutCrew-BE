## 2. 자동화 검증 결과

전체 Gradle 테스트 45개는 실패와 건너뜀 없이 성공했다. 테스트는 Flyway V1 마이그레이션과 Hibernate
`ddl-auto=validate`를 함께 실행하고, 실제 MySQL에서 고유·CHECK·외래 키·조건부 관리자
제약을 확인한다.

다음 범주를 검증했다.

1. 회원가입, 로그인, 현재 세션 로그아웃, 닉네임 변경, 회원탈퇴
2. 크루 생성, 목록, 수정, 삭제
3. 크루 가입, 탈퇴, 관리자 위임, 크루원 목록, 크루원 추방
4. CSRF 토큰 지원 작업
5. 다중 기기 세션 분리와 탈퇴 후 모든 세션 만료
6. 마지막 한 자리 동시 가입과 동일 사용자 동시 가입
7. 동시 관리자 위임, 위임과 탈퇴 경쟁, 정원 축소와 가입 경쟁
8. 잠금 실패 최대 3회 재시도와 최종 충돌 예외
9. 공통 응답의 네 필드, HTTP 상태 일치, data null 규칙, 서울 시간 형식
10. 기본·최대 페이지 크기, 허용 정렬, 빈 페이지, 3초 성능 기준
11. 비인증 상태의 검증 콘솔과 정적 자원 접근, 보호 API의 인증 유지

## 4. 구현 중 확인한 기술 제약

MySQL은 `ON DELETE CASCADE` 외래 키의 기준 열을 생성 열 식에 사용하는 스키마를 거부한다.
따라서 `manager_crew_id`는 nullable 보조 열로 구현하고 CHECK 제약과 서비스 트랜잭션에서
역할과 함께 갱신한다. 조건부 UNIQUE와 `crew_id` cascade는 모두 유지되며 도메인 모델의
역할·소속 의미는 바뀌지 않는다.

JPA가 이미 읽은 소속 엔티티를 관리하는 상태에서 DB cascade로 크루만 삭제하면 삭제된 참조를
flush하려는 문제가 있었다. 삭제 유스케이스는 소속 bulk 삭제와 영속성 컨텍스트 정리 후
크루를 삭제하도록 통일했고 회귀 테스트로 검증했다.

## 5. 남은 운영 위험

- 세션 레지스트리는 단일 인스턴스 메모리 구현이다. 다중 서버로 확장할 때는 공유 세션 저장소와
  전체 세션 만료 전략을 별도로 설계해야 한다.
- 성능 기준은 테스트 규모와 로컬 컨테이너 환경에서 검증했다. 운영 데이터 분포와 네트워크를
  반영한 부하 시험은 배포 전에 별도로 수행해야 한다.
- 운영에서는 HTTPS를 사용하고 `SESSION_COOKIE_SECURE=true` 기본값을 유지해야 한다.
